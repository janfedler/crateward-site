monica_rand_core

Back to the numbers

Version 0.10.2 of monica_rand_core copied the metadata of the widely used rand_core crate. Its build script printed every environment variable of the build into the build output, then wrote a prebuilt program for the build machine's operating system to a temporary directory and started it in the background. Anyone who built a project depending on this version ran both steps on their machine.

Behavior

All of it happens in build.rs, which Cargo runs on the building machine before compiling the crate:

  1. It prints each environment variable as a Cargo warning (cargo:warning=KEY=VALUE, line 78). For a dependency from crates.io, Cargo does not show these warnings unless asked to (-vv), but it stores them in the build directory, under target/, where build caches and CI artifacts can carry them further. In the microVM, the fake GitHub token Crateward planted in the environment ended up in that stored output.

  2. It embeds one of three prebuilt executables, chosen by operating system (helper/linux, helper/darwin, helper/windows), and writes it to /tmp/code-helper, or code-helper.exe in the temporary directory on Windows.

  3. On Linux and macOS it makes the file executable and starts it in a new session with its input and output discarded, so it outlives the build. On Windows it starts it hidden through ShellExecuteW.

In the microVM the Linux helper started, made no network attempt and exited with status 101. Crateward's VM has no internet, and the helper may behave differently elsewhere; its purpose was not analyzed further.

How Crateward found it

The version was fetched within a minute of its publication. The static analysis flagged the build script reading every environment variable, the three embedded executables and the hidden process start. The build in the microVM then showed the planted token copied into the build output. A full build in a fresh VM confirmed it, and a human reviewed the evidence. MITRE ATT&CK techniques the evidence is consistent with: T1082 (system information discovery), T1552.001 (credentials in files) and T1027.009 (embedded payloads).

Remediation

If a machine or CI job built a project depending on monica_rand_core 0.10.2:

  • Treat every secret in that build's environment as exposed: tokens, cloud keys and registry credentials. Rotate them, and check verbose build logs, build caches and CI artifacts that include target/ for the printed values.
  • Treat the machine as compromised: an unknown program ran on it, and it may still be running. Look for code-helper processes and files.
  • Replace the dependency with rand_core from the Rand project.
